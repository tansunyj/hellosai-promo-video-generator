# 单品视频生成

## 页面入口

重启服务后访问 http://localhost:4174/。默认保持原商品视频页面；切换到单品视频生成使用新增功能。

视频素材区域是同一个组件，不是两份控件。切换Tab时共享背景、BGM、上传和试听选择，原商品列表与单品选择彼此独立。

## 数据来源与文件

当前实际原目录为 public/商品目录.json，含153个商品；项目中未找到名为商品列表.json的文件。单品模块使用以下独立数据：

- data/single-product/source-products.json：原目录逐字节副本，不自动覆盖。
- public/商品文案.json：单品界面的唯一商品与文案数据源。保留原商品字段和originalProduct，另含product、story、copywriting、source、review。
- data/single-product/single-products.json：生成时同步的兼容文件，不是页面读取入口。
- source记录原始名称、原价、交付字段、数组位置和副本SHA256；导出JSON继续保存这些来源信息。

运行 npm run prepare:single 从独立源副本生成商品文案.json。若文案文件已存在会拒绝覆盖，以保护手工编辑。需要重建时先备份，再运行 npm run prepare:single -- --replace-copy；原目录与源副本不会被覆盖。页面的“重新加载单品数据”会读取该文件的新内容、清空当前页面草稿；不能代替数据转换。

## 转换原则

短商品名依据原始完整名称中的品牌、档位、期限及交付类型整理，不使用已截断的展示名补全不存在的权益。不能识别的内容采用核对提示。

期限与售后只引用原数据明确写出的内容；无质保优先于质保关键词，不能把无质保变成有质保。没有明确交付信息时，不生成秒发、自动到账等承诺。库存是副本时间点的值，不是实时库存。

所有自动生成文案都是未确认草稿。需要人工核对后勾选确认才允许导出；缺货、未知库存或停止销售提示还需单独确认。程序不验证商家的实际服务履约能力。

## 使用顺序

1. 切换单品视频生成Tab，从可搜索的独立目录选择一个商品。
2. 选择背景图片和BGM；背景图片强度可在内容编辑区调整。
3. 自动填入具体问题、卡点、对应方案、使用场景、参考价、三项购买理由、办理步骤与承接式CTA；可换一种问题切入，也可逐项修改。
4. 核对价格和实际服务，勾选确认，导出视频、PNG封面和JSON。

不同商品在当前页面会保留各自的编辑草稿；重新选择商品会取消确认和库存覆盖，防止串用上一个商品的确认状态。浏览器刷新不保存未导出的草稿，需保留内容时下载导出JSON。

## 模板与输出

单品模板为single_story，共360帧、24fps、15秒，使用现有1080×1920画布：

- 0—3秒：痛点标题、商品Logo、名称与参考价，第0帧完整可读。
- 3—6.5秒：商品与大号参考价。
- 6.5—9.5秒：三项有商品依据的购买理由依次强调。
- 9.5—12.5秒：三步选择流程。
- 12.5—15秒：品牌与单一CTA。

封面渲染第0帧，预览结束回到第0帧；暂停续播保留当前位置。封面和视频共用同一个组件与注入数据，不拼接另一张封面。

文件继续保存到output，沿用年月日时分秒前缀。导出JSON包含singleStory和singleSource，方便追踪本期实际使用的商品与文案。原模板的页面、时间轴、封面逻辑与接口不被单品模板替换。

## 当前边界

### 价格优先与省事优先（第六版）

`src/server/single-value-proposition.cjs`在五幕结构不变的情况下，先按商品选择主卖点。低预算套餐与Grok付费方案直接用「只要¥XX」做主标题，并同步强化商品承接、价格要点与CTA；普通账号不得借此冒充付费会员。成品号突出减少自行注册准备，依据具体商品信息或商家确认的场景提及收码等卡点，不承诺免扫码、免刷脸或绕过身份审核。

官方参考价放在`data/single-product/official-price-references.cjs`。只有对应套餐记录已核实、标记verified与verifiedAt且未超过有效期时，才注入官方价格；待核实候选值和过期记录不会出现在视频里。无法核实时使用「官方常规订阅嫌贵？先看这份低预算方案」与实际商品报价形成预算对照，不编造同款折扣、汇率或保证权益相同。链接时限、仅保激活和Claude无质保政策不会被卖点文案覆盖。

### 品牌卡点与商家政策（第五版）

`src/server/single-brand-scenarios.cjs`按品牌和交付类型编排整条五幕叙事：Gmail账号突出注册准备受阻，Muse成品号突出减少注册步骤，Grok含订阅账号突出支付办理，Grok代充只承接已有账号，普通号不能宣传为已含会员。多邻国与Gemini用实际参考价切入预算，并明确兑换资格、时限、首登或仅保激活等边界。

`data/single-product/merchant-rules.cjs`保存商家明确补充的口径。Claude不参与质保，该政策优先于旧商品名的质保字样；公开文案、标签、预览及导出统一执行。保留原供应商名称作为来源，不将过期承诺继续显示在画面里。未核实的注册政策只写具体用户注册受阻，不写全球关闭注册。没有同地区、同周期、同权益的官方基准，不编造差价或折扣。

`tools/upgrade-single-copy.cjs`接收升级前生成基线，备份`商品文案.json`后逐字段更新可确认的默认稿，保留识别到的人工修改；与Claude最新政策冲突的旧承诺必须覆盖。原始商品目录和源快照不变。商家反馈与外部已核实事实分开记录，生成后仍需确认实际服务条件。

### 国内用户场景与逐幕匹配（第四版）

选择商品后按服务形式和使用意图生成候选场景，依次对应「使用目标与卡点 → 对应服务 → 交付范围 → 办理与验收 → CTA」。例如充值服务承接订阅办理，账号交付承接账号准备，收码服务只承接约定收码环节；不将接码宣传成解决刷脸或身份审核。

`src/server/single-local-scenario.cjs`维护本地规则。规则不等于真实用户调查，不会证明所有国内用户均存在支付、身份或验证码障碍。未核实的卡点用条件问句，导出前由商家填写`scenarioBasis`并核对`serviceBoundary`与五幕文案。依据只留在注入JSON的`singleStory`和`singleSource.scenarioReview`，不出现在视频画面；不得填客户隐私。

接口对第三版旧稿只升级能与原始生成记录逐字段对上的文案，保留识别到的人工修改；不会重写`商品目录.json`、源快照或`商品文案.json`。编辑页可明确点击「按当前商品重新生成场景稿」重新套入整套推荐稿，取消原有确认状态。重新生成数据时仍须备份并显式使用`--replace-copy`。

每次单品导出一个商品，不把多商品挤进15秒。未实现批量单品队列、自动配音或自动发布；支持本地BGM。原目录刷新不会静默更新独立源副本，更新源数据需要明确备份并替换副本后重新转换。

## 场景文案规则（第二版）

参考片可见结构是注册问题、账号解法、商品价格、三项理由、办理步骤与CTA，而非通用商品介绍。当前只借鉴结构，不复制对方价格、品牌、老号月份、秒发或独享承诺；未依据播放数据断言爆款效果。

文案按订阅、验证、账号、兑换、资格以及品牌场景区分。例如ChatGPT充值问“想用 ChatGPT，订阅卡住了？”，Codex验证问“Codex注册，卡在验证这一步？”。已接码成品号不会被当成接码服务。质保、期限、兑换形式只引用原商品数据；无质保明确保留。商品名、Logo、价格都跟随单品ID，不能因为文案场景相似而互换。

生成是本地规则式文案，不调用外部AI接口，不会根据销量或平台热度自动优化。hookOptions提供可选切入问题；story保存默认五幕文案。编辑public/商品文案.json中的story可维护默认稿，重新加载后自动填入。

## 解决链文案（第三版）

本版不再用“想买/怎么选/先问清”代替真实卡点。每个商品保存copywriting.chain：goal（想做什么）、blocker（卡在哪一步）、solution（具体服务）、mechanism（服务如何承接）、steps与stepDetails（办理操作）、result（交付后核对什么）。story是实际可编辑与渲染的文案；copywriting.chain保留生成时的原始路径作为来源信息，页面修改后的实际内容以导出singleStory为准。

- 充值类：想开通会员 → 已有账号但没有可用支付方式？ → 店铺代充 → 确认适用账号/渠道并下单 → 对接充值 → 核对订阅状态和期限。
- 账号类：想开始使用 → 注册或验证卡住、没有账号？ → 购买现成账号 → 确认规格后下单 → 接收交付、按说明登录并核对。普通账号不宣传为付费会员，不承诺免身份审核。
- 接码类：想注册 → 卡在接收验证码？ → 接码服务 → 确认项目和接码条件 → 办理收码。不能把接码表述成解决身份审核或保证注册成功。
- 兑换类：想开通权益 → 尚未准备好兑换入口？ → 购买对应链接 → 核对兑换条件后获取链接 → 按说明兑换并检查权益。

卡点文案是目标用户场景假设，并非从商品清单中证实的平台通用要求；商家需要核对自己的目标人群和服务履约范围。原始清单没有明确服务类型的商品使用needs-review/subscription-review，不编造代充、账号交付或秒到承诺。所有商品依旧需人工核对后才能导出。

页面展示完整解决路径，步骤有独立操作说明；第二幕回答“用哪项服务解决”，第四幕具体说明怎么办理并承接结果验收，结尾按钮按代充/账号/接码/兑换分别导向对应服务。原商品模式保持不变。

## 统一模板（第四次调整）

所有商品共用同一个五幕组件：①想做什么、遇到什么问题、怎么办？②对应解决办法和价格③服务详情④操作步骤与结果核对⑤CTA与品牌结尾。第一幕不提前展示结果验收或完整解法，第二幕再回答问题；首帧仍完整展示问题、商品Logo、名称和价格。

getStoryNarrative从当前编辑的story提取统一叙事字段；视频不按品牌或商品类型分叉。商品类型只影响初始文案准备，不能改变视频结构。新增的hookQuestion独立可编辑；已有商品文案缺少该字段时兼容为“怎么办？”，读取时补全，不覆盖人工编辑。导出singleSource.copywriting.chain同步使用当前编辑内容，不再保留过期的默认路径。
